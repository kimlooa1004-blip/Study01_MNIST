# web_version — 깃허브 페이지로 배포되는 웹 앱

깃허브 페이지는 **정적 파일만** 제공한다. 서버에서 파이썬을 돌릴 수 없으므로,
학습된 가중치를 파일로 내보내 **브라우저가 직접 합성곱 계산을 수행한다.**
외부 라이브러리(CDN 포함)를 쓰지 않는다.

## 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 구성. **맨 위에 학번·이름이 보여야 한다 (과제 필수 요건)** |
| `style.css` | 화면 꾸미기. 휴대폰 화면 대응 포함 |
| `cnn.js` | 합성곱·풀링·완전연결·소프트맥스를 직접 구현한 추론 코드 |
| `app.js` | 그림 그리기, 전처리, 결과 표시 |
| `export_weights.py` | `mnist_cnn.pt` → `weights/` 변환 (개발용, 브라우저는 쓰지 않음) |
| `weights/mnist_cnn.bin` | float32 가중치 421,642개 (약 1.6MB) |
| `weights/mnist_cnn.json` | 각 층의 이름·모양·위치 설명 |

## 가중치 형식

`.bin`은 float32(리틀엔디언) 하나의 덩어리이고, `.json`이 그 안의 위치를 알려준다.
읽는 순서는 `export_weights.py`의 `층_순서`와 `cnn.js`가 맞춰져 있다.

```
conv1.weight[32,1,3,3] → conv1.bias[32] → conv2.weight[64,32,3,3] → conv2.bias[64]
→ fc1.weight[128,3136] → fc1.bias[128] → fc2.weight[10,128] → fc2.bias[10]
```

완전연결 가중치는 `[출력크기, 입력크기]` 순서의 행 우선(row-major) 배열이다.
펼치기 순서는 PyTorch와 같은 `채널 → 세로 → 가로`다. 이 순서가 틀어지면 결과가 완전히 달라진다.

## 반드시 지킬 것

- **전처리는 `desktop_version/recognize_gui.py`의 `_전처리`와 같아야 한다.** 한쪽만 고치지 않는다.
- 정규화 상수 `평균 = 0.1307`, `표준편차 = 0.3081`은 학습 때 쓴 값이라 바꾸면 안 된다.
- 모델을 다시 학습했다면 `python export_weights.py`를 실행해 가중치를 다시 내보낸다.
- 가중치 경로는 상대경로(`weights`)로 둔다. 깃허브 페이지는 `/저장소이름/` 아래에 배포되므로
  `/weights` 같은 절대경로를 쓰면 404가 난다.

## 확인 방법

`file://`로 열면 `fetch`가 막혀 가중치를 읽지 못한다. 반드시 로컬 서버로 연다.

```bash
python -m http.server 8000 --directory .
```

숫자 0~9를 직접 그려 보고, 화면 맨 위에 학번·이름이 보이는지 확인한다.

## 알아둘 점

- 확률 막대(`.막대`)는 `span`이라 `display: block`이 없으면 너비 지정이 먹지 않는다.
- 캔버스는 화면 폭에 따라 줄어들 수 있으므로, 좌표는 `getBoundingClientRect()` 비율로 환산한다.
- `touch-action: none`이 없으면 휴대폰에서 그리는 대신 화면이 스크롤된다.
