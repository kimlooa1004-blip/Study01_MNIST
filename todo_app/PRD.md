# 할 일 관리 앱 PRD

## 1. 개요

하루 10~20개 정도의 할 일을 관리하는 **개인용 웹 앱**. 브라우저에서 바로 열어 쓰고, 새로고침해도 데이터가 남는다. 서버나 빌드 과정 없이 순수 자바스크립트로 만든다.

## 2. 목표와 비목표

**목표**
- 할 일을 3초 안에 추가할 수 있을 만큼 빠르고 단순한 화면
- 오늘 얼마나 했는지 한눈에 보이는 진행률
- 새로고침·브라우저 재시작 후에도 데이터 유지

**비목표 (이번 버전에서 하지 않는 것)**
- 로그인, 계정, 서버 저장, 기기 간 동기화
- 마감일 알림, 반복 일정, 하위 작업, 공유/협업
- 프레임워크(React 등), 번들러, 외부 라이브러리 사용

## 3. 사용자와 사용 시나리오

- **사용자**: 본인 한 명.
- **시나리오**: 아침에 오늘 할 일 10~20개를 입력 → 하루 동안 완료 체크 → 카테고리별로 걸러 보며 우선순위 판단 → 저녁에 진행률 확인.

## 4. 기능 요구사항

### 4.1 할 일 CRUD (필수)
| ID | 요구사항 |
|---|---|
| F-1 | 입력창에 내용을 쓰고 Enter 또는 [추가] 버튼으로 추가한다. 빈 내용(공백만)은 추가하지 않는다. |
| F-2 | 추가할 때 카테고리를 고른다. 기본값은 마지막으로 쓴 카테고리. |
| F-3 | 항목의 내용을 더블클릭(또는 [수정] 버튼)하면 그 자리에서 수정한다. Enter로 저장, Esc로 취소. |
| F-4 | [삭제] 버튼으로 항목을 지운다. 실수 방지를 위해 삭제 직후 몇 초간 [되돌리기]를 보여 준다. |

### 4.2 완료 체크 (필수)
| ID | 요구사항 |
|---|---|
| F-5 | 체크박스로 완료/미완료를 전환한다. |
| F-6 | 완료 항목은 취소선과 흐린 색으로 표시하고, 목록 아래쪽으로 내리지는 않는다(위치가 바뀌면 헷갈리므로). |
| F-7 | [완료 항목 모두 지우기] 버튼을 제공한다. |

### 4.3 카테고리 (필수)
| ID | 요구사항 |
|---|---|
| F-8 | 카테고리는 **업무 / 개인 / 공부** 3개로 고정한다. |
| F-9 | 항목마다 카테고리 배지를 색으로 구분해 보여 준다. |
| F-10 | 상단 필터 탭 [전체 / 업무 / 개인 / 공부]로 목록을 걸러 본다. 선택한 탭도 새로고침 후 유지한다. |
| F-11 | 항목 수정 시 카테고리도 바꿀 수 있다. |

### 4.4 진행률 (필수)
| ID | 요구사항 |
|---|---|
| F-12 | 화면 상단에 **전체 진행률**(완료 수 / 전체 수, 퍼센트, 막대 그래프)을 표시한다. |
| F-13 | 카테고리별 진행률(예: 업무 3/5)도 함께 보여 준다. |
| F-14 | 할 일이 0개일 때는 0%로 나누지 않고 "할 일을 추가해 보세요"를 표시한다. |
| F-15 | 항목을 추가·수정·체크·삭제하면 진행률이 즉시 갱신된다. |

### 4.5 데이터 저장 (필수)
| ID | 요구사항 |
|---|---|
| F-16 | 모든 변경은 즉시 브라우저 `localStorage`에 저장한다. |
| F-17 | 페이지를 열 때 저장된 데이터를 읽어 화면을 복원한다. |
| F-18 | 저장 데이터가 깨졌거나 `localStorage`를 쓸 수 없으면(사생활 보호 모드 등) 빈 목록으로 시작하고, 저장 불가 안내를 화면에 표시한다. |

### 4.6 있으면 좋은 기능 (선택, 후순위)
- 내보내기/가져오기(JSON 파일)로 백업 — `localStorage`는 브라우저 데이터를 지우면 사라지므로 가장 유용한 보강책
- 날짜별 목록 분리(오늘/어제)와 지난 날 미완료 항목 이월
- 드래그로 순서 변경
- 다크 모드

## 5. 데이터 모델

`localStorage` 키 `할일앱_데이터`에 JSON 하나로 저장한다.

```json
{
  "버전": 1,
  "다음번호": 4,
  "선택한필터": "전체",
  "마지막카테고리": "업무",
  "할일목록": [
    { "번호": 1, "내용": "주간 보고서 작성", "카테고리": "업무", "완료": false, "만든시각": 1767225600000 },
    { "번호": 2, "내용": "장보기", "카테고리": "개인", "완료": true,  "만든시각": 1767225700000 }
  ]
}
```

- `번호`는 증가하는 정수로 항목을 식별한다(목록 순서·내용과 무관).
- `버전` 필드는 나중에 구조를 바꿀 때 변환용으로 쓴다.
- 10~20개/일 규모라 용량(약 5MB)은 문제되지 않는다.

## 6. 화면 구성

```
┌──────────────────────────────────────┐
│ 할 일 관리                              │
│ 전체 진행률  ████████░░░░  8/12 (67%)   │
│ 업무 3/5 · 개인 4/4 · 공부 1/3          │
├──────────────────────────────────────┤
│ [ 할 일을 입력하세요        ] [업무▼] [추가] │
├──────────────────────────────────────┤
│ [전체] [업무] [개인] [공부]               │
│ ☐ 주간 보고서 작성   (업무)  [수정] [삭제]  │
│ ☑ ~~장보기~~        (개인)  [수정] [삭제]  │
│ ...                                    │
│                  [완료 항목 모두 지우기]   │
└──────────────────────────────────────┘
```

- 단일 페이지, 위에서 아래로: 진행률 → 입력 → 필터 → 목록.
- 모바일 폭에서도 깨지지 않게 한 열 레이아웃으로 만든다.
- 키보드만으로도 추가·체크·수정이 가능해야 한다(Tab 이동, Enter, Esc).

## 7. 기술 요구사항

| 항목 | 결정 |
|---|---|
| 언어 | 순수 HTML + CSS + 자바스크립트(ES6+), 외부 라이브러리·빌드 도구 없음 |
| 파일 구성 | `index.html`, `style.css`, `app.js` 3개 |
| 저장소 | `localStorage` (동기 API, 변경 때마다 전체 저장) |
| 실행 | `index.html`을 브라우저로 열기만 하면 동작 (`file://`에서도 동작해야 함) |
| 배포 | 선택 사항. 깃허브 페이지로 올려 어디서나 열 수 있음 |
| 지원 브라우저 | 최신 Chrome, Edge, Safari, Firefox |
| 코드 구조 | 상태(데이터) → 저장/불러오기 → 화면 그리기(`그리기()`) 순의 단방향 흐름. 상태가 바뀌면 `저장()` 후 `그리기()`를 호출한다. |
| 작성 규칙 | 이 저장소 규칙에 따라 코드·주석·변수명·함수명은 한글, 파일은 UTF-8 |
| 보안 | 사용자가 입력한 내용은 `textContent`로만 화면에 넣는다(`innerHTML` 금지) |

## 8. 비기능 요구사항

- **성능**: 100개 항목까지 입력·체크 반응이 눈에 띄는 지연 없이 즉시 반영된다.
- **신뢰성**: 새로고침·탭 닫기 직후에도 마지막 변경이 남아 있어야 한다.
- **단순성**: 코드 전체 500줄 안팎으로 유지해 혼자 읽고 고칠 수 있게 한다.
- **접근성**: 체크박스·버튼에 라벨을 붙이고, 색만으로 정보를 전달하지 않는다(카테고리는 글자도 함께 표시).

## 9. 성공 기준 (수용 테스트)

1. 할 일 15개를 추가한 뒤 새로고침해도 15개와 완료 상태가 그대로다.
2. 항목을 수정·삭제·체크할 때마다 진행률 숫자와 막대가 바로 바뀐다.
3. 필터 탭을 바꿔도 진행률은 전체 기준 값과 카테고리별 값이 올바르게 표시된다.
4. 빈 내용이나 공백만 입력하면 추가되지 않는다.
5. 항목이 0개일 때 오류 없이 안내 문구가 나온다.
6. `<script>` 같은 문자열을 입력해도 그대로 글자로만 보이고 실행되지 않는다.
7. 인터넷 연결 없이도 모든 기능이 동작한다.

## 10. 위험과 대응

| 위험 | 대응 |
|---|---|
| 브라우저 데이터를 지우면 할 일이 사라짐 | 선택 기능인 JSON 내보내기/가져오기를 1순위로 추가 |
| 다른 브라우저·기기에서는 데이터가 안 보임 | 개인용 단일 브라우저 사용을 전제로 하고, 필요하면 내보내기 파일로 옮김 |
| 여러 탭을 동시에 열고 쓰면 나중에 저장한 탭이 덮어씀 | 개인용이므로 허용. 필요하면 `storage` 이벤트로 다른 탭 변경을 반영 |

## 11. 개발 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | 화면 뼈대 + 추가/삭제 + `localStorage` 저장 | 새로고침 후 유지 |
| 2 | 완료 체크 + 수정 | F-3, F-5, F-6 |
| 3 | 카테고리 + 필터 | F-8 ~ F-11 |
| 4 | 진행률 | F-12 ~ F-15 |
| 5 | 다듬기: 되돌리기, 오류 안내, 모바일 레이아웃, 접근성 | 9장 수용 테스트 전부 통과 |
| 6 | (선택) 내보내기/가져오기, 날짜 이월 | 4.6장 |

## 12. 확정이 필요한 질문

- 할 일을 **날짜별로 나눌지**, 아니면 하나의 목록을 계속 쓸지? (이 문서는 하나의 목록을 기본으로 가정)
- 완료한 항목을 다음 날 자동으로 지울지, 직접 지울 때까지 둘지? (이 문서는 직접 지우는 방식을 가정)
- 카테고리를 나중에 직접 추가·삭제할 수 있어야 하는지? (이 문서는 3개 고정을 가정)
