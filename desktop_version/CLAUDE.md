# desktop_version — PyTorch 학습 + 데스크톱 앱

창을 띄워 마우스로 숫자를 그리면 인식하는 tkinter 앱과, 그 모델을 학습시키는 코드가 들어 있다.

## 파일

| 파일 | 역할 |
|---|---|
| `model.py` | CNN 구조 정의 (`CNN모델`). 학습과 추론이 공유한다. |
| `train.py` | MNIST를 내려받아 5에폭 학습하고 `mnist_cnn.pt`로 저장 |
| `recognize_gui.py` | 그림판 + 전처리 + 예측 (`숫자인식앱`) |
| `app.py` | 실행 진입점. 바탕화면 바로가기가 이 파일을 가리킨다. |
| `icon.ico` | 앱 아이콘 (16~256px) |
| `mnist_cnn.pt` | 학습된 가중치. 테스트 정확도 99.08% |

## 모델 구조

```
입력 1x28x28
  → 합성곱(1→32, 3x3, padding=1) → ReLU → 최대풀링 2x2   (28→14)
  → 합성곱(32→64, 3x3, padding=1) → ReLU → 최대풀링 2x2  (14→7)
  → 드롭아웃(0.25) → 펼치기(3136)
  → 완전연결(128) → ReLU → 드롭아웃(0.5)
  → 완전연결(10)
```

드롭아웃은 학습에서만 동작한다. 웹 버전(`cnn.js`)에는 드롭아웃이 없는데, 같은 이유로 맞는 것이다.

## 전처리 (`recognize_gui.py`의 `_전처리`)

캔버스를 그대로 28x28로 줄이면 인식률이 크게 떨어진다. MNIST가 숫자를 20x20 상자에 맞춘 뒤
무게중심을 가운데 놓고 만든 자료이기 때문이다. 같은 순서를 따른다.

1. 밝기가 0보다 큰 영역의 외곽 상자를 찾아 잘라낸다
2. 비율을 지키며 긴 변이 20px이 되게 줄인다
3. 28x28 검은 배경 한가운데에 붙인다
4. 픽셀 무게중심을 (13.5, 13.5)로 옮긴다
5. `(값/255 - 0.1307) / 0.3081`로 정규화한다

**이 순서를 바꾸면 `web_version/app.js`의 `전처리`도 똑같이 바꿔야 한다.**

## 주의할 점

- `app.py`는 `pythonw.exe`로 실행된다(콘솔 없음). 이때 `sys.stdout`은 `None`이므로
  `sys.stdout.reconfigure(...)`를 그냥 호출하면 앱이 뜨지 않고 죽는다. 반드시 `None` 검사를 거친다.
- 콘솔이 없으면 오류가 화면에 안 보이므로, `app.py`는 예외를 잡아 메시지 창으로 띄운다.
- 경로는 `__file__` 기준 절대경로로 잡는다. 바로가기는 어느 폴더에서든 실행될 수 있다.
- 바탕화면 바로가기는 `pythonw.exe`를 대상으로 하고, `.lnk`와 앱 프로세스가 같은
  AppUserModelID(`MNIST.HandwrittenDigitRecognizer.1`)를 써야 작업 표시줄 고정이 제대로 묶인다.

## 실행

```bash
python train.py    # 학습 (CPU 기준 수 분)
python app.py      # 앱 실행
```
